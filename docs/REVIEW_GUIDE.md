# Οδηγός ελέγχου – OTDR Batch Report

Για ανεξάρτητο έλεγχο κώδικα και δοκιμές. Ο ελεγκτής **δεν αλλάζει κώδικα της εφαρμογής**.
Αναφέρει ευρήματα με: αρχείο:γραμμή, βήματα αναπαραγωγής, αναμενόμενο και πραγματικό
αποτέλεσμα, και προτεινόμενη διόρθωση.

## 1. Τι κάνει η εφαρμογή

Εφαρμογή για Windows 10/11 (Python 3.12, PySide6, reportlab) που αντικαθιστά το παλιό
`OTDR.exe` της Grandway. Η παλιά εφαρμογή άνοιγε έως 8 `.sor` και δεν έβαζε 1310 και 1550 σε
ένα PDF.

1. Φορτώνει χιλιάδες αρχεία OTDR `.sor` (Telcordia SR‑4731 v1/v2) από φάκελο.
2. Τα ομαδοποιεί σε καλώδιο → μέτρηση → μήκος κύματος, με βάση το όνομα αρχείου
   (π.χ. `FARM1.R01_SCP31_1310_0117.sor` + `FARM1.R01_SCP31_1550_0117.sor`).
3. Βγάζει μαζικά PDF: ένα ανά καλώδιο, με σελίδα σύνοψης και μία σελίδα ανά μέτρηση
   (1310+1550 μαζί), στο στυλ της αναφοράς του οργάνου Grandway FHO5000.
4. Αξιολογεί PASS/FAIL με ρυθμιζόμενα κριτήρια.

Το όνομα «OpticLink» **δεν** πρέπει να εμφανίζεται πουθενά στην εφαρμογή, στα PDF ή στο
πρόγραμμα εγκατάστασης. Αυτό είναι ρητή απαίτηση του χρήστη. Εξαίρεση είναι μόνο το όνομα του
repository.

## 2. Δομή

| Αρχείο | Ρόλος |

| `otdr_report/matching.py` | Ανάλυση ονομάτων (`parse_name`, `pair_name`), `Project` (φόρτωση με threads, αυτόματη/χειροκίνητη ομαδοποίηση) |
| `otdr_report/settings.py` | `ReportSettings`, `Thresholds`, `prepare()` (εφαρμογή launch), `event_ok()`, `evaluate()` |
| `otdr_report/pdf_report.py` | PDF: `TraceChart`, `LinkMap`, `event_rows()` (κοινό με την οθόνη), `ReportBuilder`, `generate_reports()` |
| `otdr_report/app.py` | GUI (PySide6 + pyqtgraph), εργασίες σε QThread, `--selftest` |
| `otdr_report/synthetic.py` | Γεννήτρια συνθετικών `.sor` (και με launch cable) για δοκιμές |
| `tests/` | pytest· `tests/data/` περιέχει **πραγματικά** αρχεία του χρήστη (FHO5000, 2026) και ένα δείγμα Grandway του 2012 |
| `OTDRBatchReport.spec`, `installer/setup.iss` | PyInstaller (onedir) + Inno Setup |
| `.github/workflows/build-windows.yml` | CI: pytest (Linux + Windows), PyInstaller, `--selftest` του exe, Inno Setup, artifact |

## 3. Εκκίνηση

```bash
python -m venv .venv && . .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
python -m otdr_report                                # GUI
python -m otdr_report.app --selftest out_dir         # χωρίς παράθυρο: συνθετικά .sor → PDF, γράφει out_dir/selftest.log
python -m otdr_report.synthetic data --fibers 300 --launch 100.8   # 600 δοκιμαστικά .sor
```

Σε Linux χωρίς οθόνη: `QT_QPA_PLATFORM=offscreen`. Χρειάζονται και τα πακέτα `libegl1`,
`libgl1`, `libxkbcommon0`, `libfontconfig1` και `libdbus-1-3`.

Το exe για Windows: `pyinstaller --noconfirm OTDRBatchReport.spec` και μετά `iscc installer\setup.iss`.
Το CI ανεβάζει το artifact `OTDRBatchReport-Setup-<έκδοση>`.

## 4. Δοκιμές

```bash
pytest -q          # το pytest.ini ορίζει testpaths=tests και pythonpath=.
```

| Αρχείο | Καλύπτει |
|---|---|
| `tests/test_sor.py` | ανάγνωση δείγματος 2012, round‑trip συνθετικού, μη έγκυρο αρχείο |
| `tests/test_matching.py` | ονόματα, ζευγάρωμα 1310/1550, ελλιπείς, διπλή φόρτωση, ομαδοποίηση, launch σε συνθετικά |
| `tests/test_real_files.py` | πραγματικά FHO5000: τιμές, ομαδοποίηση `scp51`, κριτήρια, launch cable, PDF |
| `tests/test_pdf.py` | ένα PDF ανά καλώδιο, ένα συνολικό PDF, ακύρωση, πραγματικό αρχείο 2012 |

Οι δοκιμές του PDF ελέγχουν ότι το αρχείο δημιουργείται και το μέγεθός του, **όχι** το
περιεχόμενο. Η οπτική επαλήθευση έγινε χειροκίνητα, με απόδοση σελίδων σε εικόνα.

## 5. Κανόνες που πρέπει να τηρεί ο κώδικας (oracle)

### Ανάγνωση SOR (ίδιοι συντελεστές με τον παλιό κώδικα Grandway, `SORPC_grandway/SorAssist.cpp`)
- θέση συμβάντος (km) = `time_of_travel × 1e‑10 × c / IOR`, όπου c = 299792.458 km/s και ο χρόνος είναι μονής διαδρομής
- απόσταση ανά σημείο = `data_spacing × 1e‑14 × c / IOR`
- καμπύλη: `(65535 − raw) × scale / 1e6` dB, όπως στην οθόνη του οργάνου (0 dB κάτω)
- launch cable = `GenParams.user_offset` (χρόνος, ίδιες μονάδες με το time_of_travel). Εκεί το γράφει το FHO5000.

### Launch cable (όπως στην οθόνη και στην αναφορά του FHO5000)
- Το συμβάν που βρίσκεται στο τέλος του launch (απόκλιση ≤ max(5 m, 5×resolution)) γίνεται **(S)** στο 0.
  Οι αποστάσεις είναι σχετικές (`rel_km`) και ό,τι βρίσκεται μέσα στο launch έχει αρνητική απόσταση.
- Το **μήκος** και η **αθροιστική απώλεια (T.Loss)** μετρούν από το (S) και περιλαμβάνουν την απώλεια του (S).
  Μέσα στο launch το T.Loss είναι «–».
- Το slope ενός συμβάντος αφορά το τμήμα **πριν** από αυτό. Απώλεια τμήματος = slope × μήκος.

Αναμενόμενες τιμές από πραγματικά αρχεία (`tests/data`, launch «από το αρχείο»):

| Αρχείο | Launch (m) | (S) απώλεια | Μήκος (m) | Συνολική απώλεια (dB) | dB/km |
|---|---|---|---|---|---|
| scp51_dis_101_1310_0001 | 100.8 | 0.449 | 48.1 | 0.464 (= τιμή του αρχείου) | 0.313 |
| scp51_dis_101_1550_0001 | 101.1 | 0.409 | 48.0 | 0.430 (= τιμή του αρχείου) | 0.439 |
| scp51_dis_207_1310_0100 | 100.8 | 0.424 | 235.3 | 0.498 (= τιμή του αρχείου) | 0.313 |
| scp51_dis_207_1550_0100 | 101.1 | 0.356 | 234.9 | 0.413 (= τιμή του αρχείου) | 0.242 |

Ο χρήστης έχει δώσει και δύο αναφορές του ίδιου του οργάνου. Δεν υπάρχουν στο repo και δεν
έχουμε τα αντίστοιχα `.sor`.

- **Στιγμιότυπο οθόνης για το `FARM1.R01_SCP34_1310_0013.sor`:** launch 100,8 m, συμβάν 0 στα
  −100,8, Seg 100,8 (0.058 dB, 0.580 dB/km), (S) 0,0, συμβάν στα 167,8, E στα 316,2,
  Total Length 316,2 m, Cumulation Loss 0,85 dB.
- **PDF του οργάνου για το `FARM1.R01_SCP31_1310_0002.sor`:** launch 102,3 m, (S) 0,0 με απώλεια
  0,508 (T.Loss 0,508), Seg 125,9 (0,048, T.Loss 0,556), NonReflect 125,9 με απώλεια 0,221
  (T.Loss 0,777), Seg 263,0 (0,074, T.Loss 0,851), E 388,8, συνολικά 0,85 dB. Όρια του οργάνου:
  Splice 0,500, Connector 0,750.

### Κριτήρια PASS/FAIL (`settings.py`)
- Από προεπιλογή μετράνε **μόνο** η κόλληση (μη ανακλαστικό, ≤ 0,30 dB) και ο connector
  (ανακλαστικό, ≤ 0,75 dB). Η ανάκλαση (−35 dB), η εξασθένηση (1310: 0,40, 1550: 0,30,
  1625: 0,35 dB/km) και η συνολική απώλεια (2,0 dB) υπάρχουν, αλλά είναι **απενεργοποιημένα**.
- Κάθε κριτήριο έχει δικό του διακόπτη. Ο γενικός διακόπτης κλειστός σημαίνει καθόλου PASS/FAIL (`None`).
- Δεν ελέγχονται: η αρχή του OTDR (`origin`), ό,τι είναι μέσα στο launch (`launch`) και το τέλος (`end`).
  Το (S) ελέγχεται ως connector.
- Μέτρηση στη σύνοψη: FAIL αν κάποιο λ είναι FAIL. «λείπει» αν λείπει λ. Αλλιώς PASS.

### Ονόματα και ομαδοποίηση (`matching.py`)
- Μοτίβα: `<όνομα>_<λ>_<αριθμός>`, `<όνομα>_<αριθμός>_<λ>`, `<όνομα>_<λ>`, `<όνομα>_<αριθμός>`,
  με διαχωριστικό `_ - . κενό`.
- Η μέτρηση εμφανίζεται με το όνομα του αρχείου χωρίς το λ (`pair_name`).
- Στην αυτόματη ομαδοποίηση, κάθε «οικογένεια» (ίδιο πρώτο τμήμα) αποφασίζεται χωριστά:
  χρησιμοποιείται το πιο αναλυτικό επίπεδο όπου ≤ 50 % των ομάδων έχουν μία μόνο μέτρηση.
  Μετά αφαιρείται από το τέλος μια λέξη χωρίς ψηφία που είναι ίδια σε όλα τα αρχεία (π.χ. `dis`).
  - `FARM1.R01_SCP31_*` → καλώδιο `FARM1.R01_SCP31`
  - `scp51_dis_101_*` και `scp51_dis_207_*` → καλώδιο `scp51`

## 6. Σημεία για ιδιαίτερο έλεγχο
1. `SorFile.apply_launch()`: όρια, ανοχή όταν ψάχνει το συμβάν του launch, launch χωρίς συμβάν
   (το «εικονικό» S, `start=-1`), συμβάντα με ίδια θέση, αρχεία χωρίς συμβάντα.
2. `_read_map` και `parse_sor_bytes`: κατεστραμμένα ή μικρά αρχεία, άγνωστα blocks
   (το FHO5000 έχει `GwParams`), SOR v1 (δεν υπάρχει πραγματικό αρχείο v1 για δοκιμή).
3. `Project._auto_level()`: μικτοί φάκελοι και ονόματα με διαφορετικό αριθμό τμημάτων.
4. Νήματα στο GUI (`Worker` / `_Job` / `run_with_progress`) και ακύρωση φόρτωσης ή PDF.
5. Το PDF να ταιριάζει με τον πίνακα σε οθόνη (κοινό `event_rows`), οι μονάδες m/km
   (όριο τα 20 km) και τα ονόματα των PDF αρχείων.
6. Μνήμη και χρόνος για 2000+ αρχεία. Μετρήσεις σε container Linux: φόρτωση 2.062 αρχείων
   ≈ 1,3 s, PDF 300 μετρήσεων ≈ 14 s.

## 7. Γνωστά θέματα και εκκρεμότητες
- Το Setup.exe δεν έχει δοκιμαστεί ακόμα σε πραγματικό υπολογιστή με Windows 11. Υπάρχει μόνο το CI.
- Το GUI έχει δοκιμαστεί μόνο σε Linux με `offscreen` (στιγμιότυπα οθόνης), όχι σε Windows.
- Εκκρεμεί απόφαση του χρήστη για το όριο κόλλησης: είναι 0,30, ενώ το όργανο χρησιμοποιεί 0,50.
- Το Link map έχει ίσες αποστάσεις ανάμεσα στους κόμβους, όχι αναλογικές όπως στο όργανο.
- Δεν υπάρχει γραμμή εντολών (CLI) για μαζική εξαγωγή. Υπάρχει μόνο το `--selftest`.
- Το μέγεθος του πακέτου PyInstaller σε Linux είναι περίπου 245 MB.
